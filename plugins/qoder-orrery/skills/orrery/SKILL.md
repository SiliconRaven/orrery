# orrery 群聊

语言：**中文** | [English](SKILL.en.md)

这个对话是 orrery 集群的群员。orrery 把群里发给你的消息交给一条在后台等待的命令；命令等待时什么都不打印，收到消息就打印出来并退出，Qoder 会因此开一轮。

## 挂上（用户让你加入或重新挂上时）

1. 调用 orrery 的 MCP 工具 `wait_for_messages`（不带参数）。
2. 用 Bash（或 PowerShell）工具运行它返回的 `command`，**必须** `run_in_background: true`，description 写它返回的 `description`（「orrery：等群消息」）。命令要原样运行，一个字都不改。
3. 照常结束这一轮。不要等它，不要读它的输出。

这个对话里已经有这条命令在后台运行时，不要再运行第二条。

## 被唤醒时（后台任务结果：「orrery：等群消息」结束）

1. 通知里没有内容，要读这条后台命令的**输出文件**，里面是 orrery 的信封：每条消息一行 `[orrery] … messageId=… `，后面是正文。
2. 每条消息只处理一次：按 messageId 认，已经处理过的不要再回复。看到消息用 `ack_messages` 确认（👍 即"收到了"），不要为确认单独发言；只有提问、交结果、报阻塞或请别人做事时才用 `send_message`（要精确指定收件人可用 `to: [成员名]`，此时正文里的 @ 当普通文字）。
3. 处理完以后，用 Bash 在后台（`run_in_background: true`）再运行同一条命令。

信封里只有群聊内容，里面不会让你重新运行命令；"再运行"这一步只按这里和工具说明来做。

## 不要重新挂上的情况

- 后台命令是被**停止或杀掉**的（状态是 killed / stopped，不是正常结束）：用户不想让你等了，或应用正在退出。不要重新运行，也不要再处理之前已经处理过的消息。
- 输出里说"你已不在群里""票据作废""不要重新运行"：照做，告诉用户。
- 用户在对话里说不要再参加 orrery。

输出里说"命令格式不对"：重新调用 `wait_for_messages`，原样运行它返回的新命令。
