# orrery 安全模型

语言：**中文** | [English](security.en.md)

本文定义 orrery 原生协作版在本机环境下防护什么、不防护什么，以及复查分级标准。

## 运行边界与信任前提

- **仅绑定回环网络**：Hub Web 服务与 MCP 端点只监听 `127.0.0.1`，不向局域网或公网开放。
- **认证隔离**：
  - Web 页面静态资源可访问，而包括 `GET /api/health` 在内的 `/api/*` 与 `/api/stream` 均受 API Bearer 令牌或 `POST /api/session` 建立的 `HttpOnly` Cookie 保护，未认证返回 `401`。
  - 原生 `/mcp` 调用方经 `x-orrery-bridge` 密钥配合宿主可控上下文认证（Codex 仅传桥密钥与运行时 `_meta.threadId`，**不传** `x-orrery-session` 或 `x-orrery-harness`；Claude/DSH/WorkBuddy/Cursor 经桥或 Hook 传会话头；ZCode/Qoder 依赖运行时 `_meta`；Antigravity 依赖 Hook HMAC 签名 `orreryCaller`）。
- **零侵入原则**：
  - 不自动安装、启用、修改第三方应用（Claude、Codex、Cursor、DSH、Kimi、ZCode、Qoder、WorkBuddy、Antigravity）的用户配置、插件或登录状态。
  - 只往集群明确接入的目标会话写入投递；读取本地列表采用只读访问或临时副本，不修改原始会话库（原生对话自身运行仍会按目标应用机制落盘其会话历史）。
- **不主动启动用户原生应用**：适配器、桥和插件绝不拉起未运行的桌面客户端（唯一例外是在受信任的 Electron 桌面壳内由用户亲自点击 `+` 面板触发启动）。应用退出即离线，不保留补发队列。
- **继承用户自身应用权限**：原生对话按你在宿主应用中的审批预设执行操作；orrery 不替用户放宽权限，也不保证每次操作必定弹框确认。
- **Kimi 令牌例外**：`~/.kimi-code/server.token` 仅留在内存，且在 Windows 核验进程映像（`Kimi Code.exe` / `kimi.exe`）与 `netstat` TCP 监听 PID 一致后，方经无代理回环请求发往本机实例，绝不写日志或数据库。

## 主要防护范围

1. **禁止未授权网络访问**：回环绑定与 API/Bridge 认证阻断局域网或公网越权调用。
2. **防止同一系统内会话冒充**：模型无法在工具参数中自称别的群员；非签名通道的参数不作身份依据。
3. **成员隐身由 Hub 强制执行（`hiddenAt`）**：隐身**不只是界面隐藏**。Hub 会拒绝向隐身成员投递新消息、拦截其一切 MCP 工具调用（含读取工具一律返回提示并空操作）、阻止向其派发新任务或 `@` 唤醒，且在除用户和启用中的协调员外对其他成员不可见；已有消息和任务记录保留。
4. **发件箱防逃逸**：原生成员通过 `send_message` 的 `attachments` 附带发件箱副本时，禁止目录分隔符、UNC 路径、符号链接与多硬链接，且仅限复制（不改动或删除原件）。
5. **回收站彻底清理**：`POST /api/clusters/:id/purge` 清除对应软删除集群的全部消息、任务与无主附件；依赖 SQLite 页机制，不保证物理盘底层扇区零擦除。
6. **外部插件非 OS 沙箱**：外部插件（[外部插件说明](external-plugins.md)）运行在独立 OS 子进程中；`permissions`、`clusterIds`、`writeClusterIds` 与 `mentionEnabled` 仅约束其通过 orrery 协议能访问或唤醒的群聊范围，不能取代系统级沙箱，请只运行可信代码。

## 不在防护范围内（Non-goals）

- **拥有同操作系统用户权限的恶意本机程序**：能直接读取 `~/.orrery/secret`、`api-token`、`hub.json` 或篡改插件文件的本机程序与当前用户同权，不属于本威胁模型防护范围。
- **用户自行开启的全自动审批**：若用户在原桌面端开启自动运行命令/工具，来自集群的 `@` 将自动执行。
- **第三方应用合规与云端行为**：各外部客户端服务条款（如 Antigravity 风险提示）与供应商服务端行为由用户自行评估。

## 问题严重度分级

- **P1（阻断级）**：可利用的安全漏洞、身份冒充、越权主动启动第三方应用或导致数据损坏丢失的问题，必须修复并复核通过。
- **P2（主要问题）**：明显影响稳定性、错误边界或功能契约但无直接安全/数据丢失风险的问题。
- **P3（加固项）**：超出本威胁模型的纵深防御建议与理论边界。
